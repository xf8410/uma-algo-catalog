# 第 8 族：偏好学习 / 排序 / RLHF

> 一句话：当"好坏"没法用单一分数定义、只能靠"人工比 A 还是 B 好"来表达时，用这族算法把偏好排出来、学出来。

**整族对赛马娘的结论**：核心奖励是"评分"——它本身就是明确的数字，**不需要 RLHF 那套对齐**。唯一要借的是 **Bradley-Terry 成对比较**，用在 holdout 验收上（tier2 #8）。其余的 RLHF/DPO 全家判不适用。

---

## 成对比较（我们要借的那半）

### Bradley-Terry / Thurstone / Plackett-Luce
- **干什么用**：把"两两比较谁更好"建模成胜率，反推每个对象的内在实力分。BT 是两两版，Thurstone 加了高斯噪声，Plackett-Luce 是多人排序版。
- **怎么调**：BT 几乎无超参；Thurstone 调噪声方差。
- **怎么提升**：比"比绝对分"更抗噪声——只关心"同种子下谁高"，不关心绝对数值波动。
- **对赛马娘帮助**：🔄 **排队（tier2 #8）**。holdout 验收从"均值差"升级成"配对胜率"，统计功效更高——正适合我们"评分噪声大"的病。

### GP preference learning / Preference-based BO
- **干什么用**：把 GP 用在"偏好询问"上，用尽量少的对比问出最优参数。
- **怎么调**：GP 核、询问策略（主动挑哪对来比）。
- **怎么提升**：当打分很贵但"人工比对"可行时最划算。
- **对赛马娘帮助**：⬜ 未试。评分自动化了，不需要人工偏好，非优先。

## 排序学习（Learning to Rank）

### RankNet / LambdaRank / ListNet / RankBoost / Ranking SVM
- **干什么用**：从"排序关系"里学一个排序函数，搜索引擎常用——LambdaRank 还带"位置折扣"（列表前几名更重要）。
- **怎么调**：网络结构、pairwise/listwise 损失、NDCG 折损。
- **怎么提升**：当目标是"排出好几个候选的先后"，而不是"给单个打分"时对口。
- **对赛马娘帮助**：⬜ 未试。我们的验收是"单个最优"而非"列表排序"，除非未来要做"给玩家推荐多套候选排序"。

## RLHF / 对齐（判不适用那半）

### RLHF / DPO / IPO / KTO / ORPO / SimPO
- **干什么用**：先用人对齐出"奖励模型"，再让策略按奖励优化，或直接用偏好数据训策略（DPO 跳过奖励模型）。IPO 防过拟合偏好，KTO 用 Kahneman-Tversky 损失，ORPO/SimPO 更省。
- **怎么调**：参考模型、KL 惩罚系数 β、偏好数据质量。
- **怎么提升**：语言模型对齐的黄金标准。
- **对赛马娘帮助**：🚫 **不适用。** 奖励 = 评分，定义明确不模糊。RLHF 是给"说不出好坏、只能靠人点"的场景用的，我们不需要。

---

## 族总结

| 状态 | 算法 |
|---|---|
| 🔄 排队 | Bradley-Terry（holdout 成对验收） |
| ⬜ 未试 | Ranking SVM/LambdaRank 等（除非做候选排序） |
| 🚫 不适用 | RLHF/DPO/IPO/KTO/ORPO/SimPO（奖励明确） |
